# 주간 정기회의 보고서

> **버전 v2.2.0** — 변경 시 §버전 관리 규칙에 따라 bump 하고 **세 곳(본 파일 상단·`frame.html` 상단 주석·산출 아티팩트 footer)을 동기화**한다. 이력은 [CHANGELOG.md](CHANGELOG.md).
>
> **성격: 매주 정기회의 5분 발표용.** 목적은 **"이정도 진행됐다(러프한 진행상황) + 다음에 뭘 한다"** 를 빠르게 공유하는 것 — 상세 회고가 아니다. 직전 한 주의 일일 보고서를 참고해 메인 task 를 **큰 카테고리 3~4개**로 묶고, 각 과제에 **상태(완료/진행중/예정) + 진행률**을 달아 한눈에 보이게 한다. 본문은 **현황(어디까지) → 다음(할 것)** 으로 러프·간결하게(항목당 ~1분). 데모뷰는 가능하면 첨부.
>
> **적용 범위: 프로젝트 무관 공용.**
>
> **daily-report 스킬과의 관계**: 컴포넌트 구조(카드/체크리스트)를 따르되 색은 회의 보고용 **고대비 팔레트로 재정의**한다(일일의 저채도 톤이 "애매"하다는 피드백 → 선명한 블루 accent·진한 텍스트/테두리·카드 그림자). 그 위에 **그라데이션 히어로 + 스탯 대시보드 + 카테고리별 데모뷰 + 일자별 타임라인 + 스크롤/호버 모션**을 얹는다.

## 0. 설정 — 첫 실행 때 한 번만 묻는다

보고서를 만들기 **전에** [`~/.claude/chan-reports/report-config.json`](~/.claude/chan-reports/report-config.json) 을 Read 한다(daily-report 스킬과 **같은 파일을 공유**한다 — 한쪽에서 만들었으면 다시 묻지 않는다).

| 상태 | 할 일 |
|---|---|
| 파일이 있고 `author` 가 채워져 있다 | 그대로 쓴다. **묻지 않는다** |
| 파일이 없거나 `author` 가 비어 있다 | 아래를 **한 번에** 묻고, 답으로 파일을 만든 뒤 진행한다 |

> 보고서에 쓸 **이름**과 **직함**을 알려주세요 (예: `홍길동 / 주임`).
> PDF 를 공유드라이브에도 올리시려면 rclone remote 이름과 폴더 경로도요 — 안 쓰시면 "없음".

```json
{
  "author": "홍길동",
  "authorTitle": "주임",
  "org": "우리팀",
  "rclone": { "remote": "gdrive", "parent": "보고서/일일" },
  "uploadHtml": false
}
```

`author`+`authorTitle` → 헤더 작성자 `{{AUTHOR}}` · 파일명. `org` → 푸터 `{{ORG}}`.
★**업로드 폴더는 `parent/author` 로 자동 조립되고 없으면 `publish.ps1` 이 만든다** — 사람마다 자기 이름 폴더라 같은 부모를 공유해도 안 겹친다. `rclone.*` 가 비면 **업로드를 건너뛴다**(PDF 는 생성됨).
⚠️ **이미 있는 파일을 덮어쓰지 않는다.**

**드라이브를 처음 연결한다면** — `daily-report` 스킬의 **§0.1 드라이브 연결** 7단계를 그대로 따른다(설치 확인 → `rclone config` 입력 순서 제시 → 연결 검증 → 부모 폴더 선택 → 본인 폴더 생성). ⚠️ `rclone config` 는 대화형이라 **내가 실행하지 않는다.**

## 1. 보고 주기 · 기간 규칙 (필수)

- **정기회의 = 매주 수요일** 기준. (회의 요일이 다르면 그 요일로 바꿔 계산한다.)
- **회의일 D** = 보고 주의 회의 요일.
- **보고 기간** = `(D − 7일)` ~ `(D − 1일)`. 수요일 회의면 **지난주 수 ~ 이번주 화**의 7일.
- 이 기간의 **일일 보고서들을 참고**해 메인 task 를 추린다(커밋/PR 은 같은 기간 `git log --since/--until`·merged PR 로 교차 확인, **지어내지 않는다**).

## 2. 제목 규칙 (필수)

`{{MONTH}}월 {{WEEKNUM}}주차 주간 정기회의 보고서`

- **MONTH** = 회의일 D 의 월.
- **WEEKNUM** = D 가 그 달의 몇째 주 = `ceil(D.일 / 7)` (1~7일 → 1주차, 8~14 → 2주차 …).
- 예: 회의일 2026-07-01(수) → "7월 1주차 주간 정기회의 보고서", 기간 2026-06-24(수) ~ 2026-06-30(화).
- 히어로 고스트 숫자(`{{GHOST}}`)는 `월·주차` 압축 표기(예: `7·1`) 등 장식용.

### 파일명

`{YYMMDD}-주간보고서-{AUTHOR} {AUTHOR_TITLE}` — 회의일 기준 날짜 접두. 예: `260708-주간보고서-홍길동 주임.html` / `.pdf`.

## 3. 메인 과제 = 큰 카테고리 3~4개

- 그 주 작업을 큰 카테고리(메인 task)로 묶는다. **기본 3개**, 도메인상 중요한 작업이 별도 축이면 **4개**까지(`w4` 추가). 5개 이상 나열 금지, 2개 이하로 줄이지도 않는다.
- **번호 동적**: 카드 K개 → 타임라인 `(K+1)`(기본 마지막). 다음 단계는 기본 미표시 — 사용자 지시로 넣을 때만 `(K+2)`. (프레임 `{{NT}}`·`{{NN}}`)
- 작은 작업·커밋은 카테고리 안으로 **병합**한다. 카테고리는 "그 주 그 영역에서 이룬 것".
- 각 카드 = `[TAG][카테고리]` 제목 + **상태 배지 + 진행률 바** + **현황**(어디까지, 1~2 불릿) → **다음**(다음 할 것, 1 불릿) + **데모뷰**(선택).
- 발표 흐름이 "이건 이정도 됐고(현황+진행률), 다음은 이거(다음)"가 되게 — 회고형 '성과' 나열 대신 **현재 상태 + 다음 액션** 중심.
- 본문은 **개조식(불릿) 강제** — 줄글 금지. 카드당 현황 1~2 + 다음 1.
- TAG/색은 daily-report 와 동일(FEAT·BUG·FIX·CHORE·DOCS). 카테고리 성격에 맞는 대표 TAG 1개씩.

## 4. 진행 상태 (상태 배지 + 진행률 — 필수)

"이정도 진행됐다"를 한눈에 보이는 핵심 장치. 카드마다:

- **상태 배지**: `완료`(class `done`, 녹색) / `진행중`(class `wip`, 블루) / `예정`(class `todo`, 회색) 중 하나. `.status`·`.progress` 의 class 를 함께 맞춘다(예: `class="status done"` + `class="progress done"`).
- **진행률 바**: `.progress .bar > i` 의 `--p: NN%` + `.pct` 의 `NN%`. 완료=100, 진행중=대략치(러프해도 됨), 예정=0~10.
- **히어로 대시보드**: 커밋/PR 활동량이 아니라 **상태 지표** — `메인 과제 {n}` · `완료 {n}` · `진행 중 {n}`. 회의에서 중요한 건 활동량이 아니라 완료/진행 상태다.

## 5. 데모뷰 (각 카테고리마다, 가능하면)

카테고리 1건당 `.demo` 1개. 우선순위:

1. **캡처/GIF** — `<img src="data:image/png;base64,…">`. **외부 URL 금지**(CSP — data-URI 만).
2. **인라인 SVG 스키매틱** — 기능을 도형으로. 프레임의 `.d-block`·`.d-port`·`.d-edge`·`.d-pill`·`.d-txt` 토큰 클래스를 써 다크/라이트 자동 대응. 실제 캡처가 없을 때 권장.
3. **둘 다 불가** — `.demo.placeholder` 로 `데모 준비중` 캡션(빈칸으로 두지 않는다).

하단 `.demo-cap` 에 "무엇을 보여주는지" 한 줄 캡션.

## 6. 일자별 타임라인 (선택)

> 5분 발표에선 보조 — 진행상황은 카드의 상태/진행률이 1차다. 흐름 맥락이 필요할 때만 넣고, 시간이 빠듯하면 생략 가능(섹션 통째 삭제 + 번호 재정렬).

`section#timeline` 세로 레일. 보고 기간의 **요일별 한 줄** + 그날 작업 요약 + `↗ 일일 보고서` 링크. "무엇을"은 카드, "언제"는 타임라인. **다음 단계를 미표시하면(기본) 타임라인이 마지막 섹션**이다.

**일일 보고서 링크 자동 연결 (필수)**: 각 일자의 `↗ 일일 보고서` URL 은 [`~/.claude/chan-reports/artifact-urls.md`](~/.claude/chan-reports/artifact-urls.md) 에서 **직접 조회해 자동으로 단다**(사용자에게 매번 묻지 않는다). 그 파일에 없는 날만 링크 생략 — **인덱스가 비어 있으면 링크 없이 타임라인만** 만든다(그것도 정상 동작이다).

**표시 규칙 (필수)**:

- **평일**: 작업 없어도 행 표시 — `.check.empty`(`작업 없음`, 점 흐리게).
- **토·일**: **일일 보고서가 있을 때만** 행 표시. 없으면 **행 자체를 생략**한다(`작업 없음`으로도 넣지 않는다). → 타임라인 행은 5~7개.

## 7. 다음 단계 · 논의 (기본 미표시 — 옵트인)

- **기본은 넣지 않는다.** 사용자가 **명시적으로 지시할 때만**(예: "다음 단계 넣어") `section#next` 를 포함한다.
- 미포함이 기본이므로 그때는 `#next` section + 목차/점프바 줄을 삭제하고, **타임라인이 마지막 섹션**(번호 = 카드수+1).
- 포함 시 번호 = 카드수+2. 회의 액션 아이템 위주로 짧게.
- (과제별 "다음 할 것"은 각 카드의 **다음** 행에 이미 있으므로, 이 패널이 없어도 다음 액션은 카드에서 보인다.)

## 8. 빈 항목 처리 규칙 (강제)

- '일자별 타임라인' 섹션은 삭제 금지 — 평일 빈 날은 `작업 없음`, 토·일은 일일 보고서 없으면 행 생략(§6).
- '다음 단계 · 논의'는 §7 대로 **기본 미표시**(빈 항목 강제 대상 아님).
- 데모뷰는 빈칸 금지 — 없으면 `.demo.placeholder`.

## 9. 줄바꿈(워드랩) 규칙 (필수)

한글 어절 단위 줄바꿈(`word-break: keep-all`, 프레임 `body`). 긴 토큰만 `overflow-wrap: break-word`. 카드 제목 글자 단위 잘림 금지.

## 11. 재사용 프레임

완성 프레임은 **[`frame.html`](frame.html)** (이 폴더). CSS·토큰·TOC·점프바·인쇄·다크·스크립트가 모두 들어 있다. **CSS/스크립트는 손대지 않는다(프레임 = 고정).**

채울 곳: `{{PROJECT}}`(eyebrow)·`{{MONTH}}`·`{{WEEKNUM}}`·`{{MEETING_DATE}}`·`{{START}}`·`{{END}}`·`{{AUTHOR}}`·`{{GHOST}}`·지표 3개·`{{TAG}}`·카테고리 제목·상태/진행률·현황/다음 불릿·데모뷰·타임라인 행·목차/점프바.

카테고리 카드 3~4개(기본 3, 4번째는 `w4` 슬롯). **`w4` 를 안 쓰면 그 `article` 과 목차·점프바 줄을 삭제**하고 `{{NT}}`·`{{NN}}` 을 04·05 로 맞춘다.

## 12. 실행 방식 (직접 작성)

보고서 생성/갱신은 **위임하지 말고 직접** 작성한다 — 프레임 채우기·Artifact 발행·업로드를 순차 수행한다.

## 13. 절차

1. `frame.html` 복사 → `{{…}}` 채우기 → 카테고리 카드 3~4개 → 각 카드 데모뷰 채우기.
2. 제목/기간/지표를 §1·§2 로 계산해 채운다.
3. (필요 시) `artifact-design` 스킬 로드 — **프레임이 디자인을 고정하므로 레이아웃 변경 없이 내용만**.
4. Artifact 도구로 발행. 같은 주 갱신은 동일 file_path 재사용. **채운 HTML 은 `~/.claude/chan-reports/reports/{YYMMDD}-주간보고서-{AUTHOR} {AUTHOR_TITLE}.html` 로 저장**한다.
5. 발행 URL 을 `~/.claude/chan-reports/artifact-urls.md` 의 **주간 표**에 Read 후 행 추가.
6. **공유드라이브 업로드** — `../daily-report/publish.ps1 -Html "<저장한 html 경로>"`. 스크립트·rclone 이 없으면 건너뛰고 그 사실을 보고에 한 줄.

## 14. 버전 관리 (SemVer 변형)

- **MINOR +1, PATCH=0** — 새 기능/대폭 수정(섹션·구조·디자인 큰 변경).
- **PATCH +1** — 단순 수정(문구·소규모 스타일·플레이스홀더·오타).
- **MAJOR +1** — 전면 재설계(호환 불가).
- 변경 시 **반드시** ① 본 파일 상단 ② `frame.html` 상단 주석 ③ 산출 아티팩트 footer 를 동일 갱신 + [CHANGELOG.md](CHANGELOG.md) 한 줄.
